# 파이썬 기본 문법 학습 페이지 개발 문서

## 1. 문서 목적

브라우저에서 파이썬 기본 문법을 학습하고, 작성한 코드를 직접 실행하며, 실습과 평가 결과를 확인할 수 있는 학습 페이지를 개발한다.

구현 대상 파일은 `python-basics.html` 단 하나다. 별도 백엔드, 로컬 개발 서버, 데이터베이스 없이 HTML 파일을 브라우저에서 직접 열어 사용할 수 있어야 한다.

## 2. 요구사항

### 2.1 필수 요구사항

| 번호 | 요구사항 | 완료 기준 |
| --- | --- | --- |
| 1 | 단일 HTML 파일 | HTML, CSS, JavaScript, 학습 콘텐츠가 `python-basics.html` 안에 들어 있다. 실행에 필요한 별도 프로젝트 빌드가 없다. |
| 2 | 코드 입력 | 학습자가 여러 줄의 파이썬 코드를 편집할 수 있다. 코드 입력 영역은 고정 높이 또는 최소 높이를 가져야 하며 내용에 따라 레이아웃이 무너지지 않는다. |
| 3 | 코드 실행 | 실행 버튼을 누르면 입력한 파이썬 코드가 브라우저에서 실행되고 표준 출력과 오류가 결과 영역에 표시된다. |
| 4 | 서버 불필요 | `python-basics.html`을 파일 탐색기에서 직접 열어도 화면이 동작한다. Node.js, Python HTTP 서버, API 서버를 요구하지 않는다. |
| 5 | 객관식 평가 | 선택지를 고르고 채점하면 점수와 문항별 정답/해설이 표시된다. |
| 6 | 주관식 평가 | 출력 결과, 빈칸 코드, 짧은 설명을 직접 입력하는 문항이 포함된다. 제출 후 정답 여부와 해설을 확인할 수 있다. |
| 7 | 진행 상황 저장 | 학습 완료, 실습 답안, 평가 결과를 브라우저의 `localStorage`에 저장한다. 서버로 전송하지 않는다. |

### 2.2 학습 범위

기존 8개 챕터의 내용을 유지한다.

1. 값과 변수
2. 자료형과 형변환
3. 연산자
4. 문자열 다루기
5. 리스트와 딕셔너리
6. 조건문
7. 반복문
8. 함수

각 챕터는 설명, 실행 가능한 예제, 예상 출력, 자주 발생하는 오류, 요약으로 구성한다.

## 3. 현재 구현 상태와 보완 범위

현재 `python-basics.html`에는 학습 콘텐츠, 코드 편집·실행 패널, 12개 실습, 객관식 10개와 주관식 5개 평가, 단계 잠금, `localStorage` 기반 진행 상황 저장이 구현되어 있다.

코드 실행은 Pyodide CDN을 사용하며, 실행 결과와 오류를 각 코드 패널에 표시한다. 평가 점수는 객관식 10점과 주관식 5점을 합산해 15점 만점으로 표시한다.

## 4. 화면 구성

### 4.1 상단 상태 영역

- 페이지 제목과 학습 안내
- 학습 진행률: `학습 0/8`
- 실습 진행률: `실습 0/12`
- 평가 점수: 채점 전 `평가 -`, 채점 후 `평가 8/10`
- Python 기준 버전 표시: `Python 3.14 기준`

### 4.2 단계 내비게이션

세 단계 탭을 사용한다.

1. 학습: 8개 챕터를 읽고 예제를 실행한다.
2. 실습: 주관식 또는 코드 작성형 12문제를 푼다.
3. 평가: 객관식과 주관식 문항을 채점한다.

기존 정책대로 앞 단계 완료 전에는 다음 단계를 잠근다. 단, 학습자가 이미 저장된 진행 상황을 가지고 있으면 저장된 지점부터 복원한다.

### 4.3 코드 실행 패널

각 실행 패널은 다음 요소를 갖는다.

- 문제 또는 예제 설명
- 여러 줄 코드 입력창
- `실행` 버튼
- `초기 코드 복원` 버튼
- 실행 상태: 대기, 실행 중, 완료, 오류
- 출력 영역
- 오류 영역

권장 HTML 구조:

```html
<section class="runner" data-runner="chapter-1-example">
  <label for="code-chapter-1">코드</label>
  <textarea id="code-chapter-1" spellcheck="false"></textarea>
  <div class="runner-actions">
    <button type="button" data-action="run">실행</button>
    <button type="button" data-action="reset">초기화</button>
  </div>
  <pre class="runner-output" aria-live="polite"></pre>
</section>
```

코드 입력창은 `Tab` 키를 눌렀을 때 포커스를 잃지 않고 공백 4칸을 삽입하면 좋다. 모바일에서는 가로 스크롤이 생기더라도 코드가 줄어들어 읽기 어려워지지 않도록 한다.

## 5. 브라우저 안에서 파이썬 실행

### 5.1 실행 방식

Pyodide를 브라우저에서 로드해 파이썬 코드를 WebAssembly로 실행한다.

```html
<script src="https://cdn.jsdelivr.net/pyodide/v0.27.2/full/pyodide.js"></script>
```

초기 실행 시 런타임을 비동기로 준비한다.

```javascript
let pyodidePromise;

function getPythonRuntime() {
  if (!pyodidePromise) {
    pyodidePromise = loadPyodide({
      indexURL: "https://cdn.jsdelivr.net/pyodide/v0.27.2/full/"
    });
  }
  return pyodidePromise;
}
```

이 방식은 서버를 필요로 하지 않지만, 처음 런타임을 내려받을 때 인터넷 연결이 필요하다. 이미 브라우저 캐시에 런타임이 있으면 재사용할 수 있다. 완전 오프라인까지 지원해야 할 경우 Pyodide 파일을 HTML과 함께 내장하거나 별도 로컬 리소스로 묶는 후속 작업이 필요하다.

### 5.2 표준 출력과 오류 수집

실행 전 `sys.stdout`과 `sys.stderr`를 `io.StringIO`로 바꾸고, 실행 후 원래 스트림을 복원한다. 출력과 오류는 텍스트로 변환해 각각 결과 영역에 표시한다.

실행 결과는 다음 형태로 관리한다.

```javascript
{
  status: "success", // loading | running | success | error
  stdout: "10\n",
  stderr: "",
  errorType: "",
  durationMs: 42
}
```

오류가 발생하면 페이지 전체를 중단하지 않고 해당 실행 패널에만 다음을 표시한다.

- 예외 유형: `SyntaxError`, `NameError` 등
- 파이썬 오류 메시지
- 가능한 경우 오류가 발생한 줄 번호
- 다시 실행할 수 있는 `실행` 상태

### 5.3 실행 제한

학습 페이지가 멈추지 않도록 다음 정책을 적용한다.

- 실행 버튼을 누르는 동안 같은 패널의 실행 버튼을 비활성화한다.
- 무한 반복 가능성이 있는 코드는 Web Worker에서 실행하는 구조를 우선한다.
- 실행 시간이 제한을 넘으면 Worker를 종료하고 `실행 시간이 초과되었습니다.`를 표시한다.
- 페이지의 DOM, `localStorage`, 브라우저 전역 객체를 파이썬 코드에 직접 노출하지 않는다.
- 파일 읽기, 네트워크 요청, 브라우저 제어는 학습 범위에서 지원하지 않는다.

단순 구현에서 Web Worker를 바로 사용하기 어렵다면 1차 버전에서는 짧은 예제만 실행하고, 실행 제한을 후속 작업으로 분리한다. 단, 사용자에게 실행 제한이 있음을 표시해야 한다.

## 6. 실습과 평가 설계

### 6.1 실습 12문제

기존 실습 문항을 유지하되 문항 유형을 다음처럼 구분한다.

| 유형 | 예시 | 채점 방식 |
| --- | --- | --- |
| 실행 결과 | `print(9 // 2, 9 % 2)`의 출력 | 공백과 줄바꿈을 정규화한 뒤 비교 |
| 빈칸 코드 | `print(___(word))` | 정답 표현과 비교 |
| 코드 작성 | 1부터 5까지 출력하는 코드 작성 | 실행 결과와 필요 조건을 함께 검사 |
| 짧은 설명 | `/`와 `//`의 차이 설명 | 핵심 키워드 포함 여부와 수동 확인용 결과 표시 |

실습 문항 데이터는 화면 생성 코드와 분리해 배열로 관리한다.

```javascript
const PRACTICE = [
  {
    id: "practice-01",
    type: "output",
    prompt: "다음 코드의 출력 결과를 입력하세요.",
    starterCode: "x = 4\nx = x + 6\nprint(x)",
    answer: "10",
    explanation: "x는 4에서 10으로 바뀝니다."
  }
];
```

실습 통과 기준은 기존 흐름에 맞춰 12문항을 모두 맞히는 것으로 한다. 답안은 채점 전에도 `localStorage`에 임시 저장한다.

### 6.2 객관식 평가

- 10문항
- 문항별 단일 선택
- 전체 제출 후 한 번에 채점
- 점수, 정답, 선택한 답, 해설 표시
- 재응시 버튼 제공

### 6.3 주관식 평가

평가에는 최소 5개의 주관식 문항을 포함한다.

권장 구성:

- 출력 결과 입력 2문항
- 코드 빈칸 입력 1문항
- 짧은 코드 작성 1문항
- 개념 설명 1문항

주관식 자동 채점 규칙은 문항별로 명시한다.

1. 출력 결과: 앞뒤 공백 제거, 줄바꿈을 `\n`으로 통일한 뒤 완전 일치
2. 빈칸 코드: 앞뒤 공백 제거 후 허용 정답 배열과 비교
3. 짧은 코드 작성: Pyodide로 실행하고 지정 출력과 비교
4. 설명: 대소문자와 공백을 무시하고 필수 키워드가 모두 포함되는지 확인
5. 자동 채점이 모호한 설명 문항은 `부분 확인 필요`로 표시하고 정답 예시를 제공한다.

주관식 데이터 예시:

```javascript
{
  id: "written-01",
  type: "written-output",
  prompt: "다음 코드의 출력 결과를 입력하세요.",
  code: "print(10 / 2)",
  answers: ["5.0"],
  explanation: "/ 연산자는 나누어떨어져도 실수를 반환합니다."
}
```

최종 점수는 객관식과 주관식을 합산한다. 주관식 코드 실행 문항이 실행 오류이면 오답으로 처리하고 오류 내용을 피드백한다.

## 7. 상태 저장

저장 키는 버전을 포함해 충돌을 피한다.

```javascript
const STORAGE_KEY = "python-basics-progress-v2";
```

저장 데이터 예시:

```javascript
{
  version: 2,
  activePhase: "practice",
  completedChapters: [0, 1, 2],
  practiceAnswers: {
    "practice-01": "10"
  },
  practiceResults: {
    "practice-01": true
  },
  quizAnswers: {
    "quiz-01": "2",
    "written-01": "5.0"
  },
  quizResult: null
}
```

`localStorage`를 사용할 수 없는 사생활 보호 모드에서는 현재 세션만 동작하도록 오류를 무시하고 안내 문구를 표시한다. 저장 데이터에는 사용자 이름, 이메일, 외부 식별자 등 개인정보를 넣지 않는다.

## 8. 접근성 및 사용성

- 모든 입력창에는 연결된 `label`을 둔다.
- 결과 영역은 `aria-live="polite"`를 사용한다.
- 색상만으로 정답/오답을 구분하지 않고 텍스트 상태도 함께 표시한다.
- 키보드만으로 챕터 이동, 코드 입력, 실행, 제출이 가능해야 한다.
- 실행 중에는 로딩 상태를 표시하고 중복 실행을 막는다.
- 작은 화면에서는 실행 결과가 입력창과 겹치지 않도록 세로로 배치한다.
- `prefers-reduced-motion: reduce` 설정에서는 애니메이션을 끈다.

## 9. 파일 및 외부 의존성 정책

- 필수 구현 파일: `python-basics.html`
- 학습자용 정적 문서: `python-basics.md`
- 개발 문서: `python-basics-development.md`
- 별도 JavaScript, CSS 파일은 만들지 않는다.
- Pyodide CDN은 유일한 필수 외부 런타임 의존성이다.
- Google Fonts와 같은 장식용 외부 리소스가 실패해도 학습, 실행, 채점은 동작해야 한다.

## 10. 검증 시나리오

다음 순서로 브라우저에서 `python-basics.html`을 직접 열어 확인한다.

1. 파일을 더블 클릭해 페이지가 열리는지 확인한다.
2. 학습 예제에서 `print(2 + 3)`을 실행해 `5`가 출력되는지 확인한다.
3. `print(1 / 0)`을 실행해 페이지가 멈추지 않고 오류가 표시되는지 확인한다.
4. 문법 오류 코드를 실행해 `SyntaxError`와 재실행 버튼이 표시되는지 확인한다.
5. 실습 답안을 입력하고 새로 고친 뒤 답안이 복원되는지 확인한다.
6. 출력 결과 주관식에 `5.0`을 입력해 정답 처리되는지 확인한다.
7. 공백이 포함된 동일 답안이 정답 처리되는지 확인한다.
8. 틀린 주관식 답안을 제출해 오답과 해설이 표시되는지 확인한다.
9. 객관식과 주관식을 모두 제출해 합산 점수가 표시되는지 확인한다.
10. 진행 상황 지우기를 눌러 저장된 답안과 점수가 초기화되는지 확인한다.
11. 브라우저 창 너비를 모바일 수준으로 줄여 입력창, 출력, 버튼이 겹치지 않는지 확인한다.
12. 개발 서버를 실행하지 않은 `file://` 경로에서도 위 시나리오가 동작하는지 확인한다.
